# 企业知识库迁移试点方案

> 本文件是功能测试用的虚构复杂输入。数字与引语均为用户提供的示例数据，未做外部核验，不代表真实企业或调研结论。

## 现状

- 示例盘点记录显示，试点团队现有 1,240 份活跃文档，分布于 3 个共享目录。
- 示例抽样记录显示，28% 的文档存在两个或更多“最终版”文件名。
- 示例访谈记录称：“我们最耗时的不是写文档，而是判断哪一份还能用。”

## 核心判断

- 与其一次性迁移全部历史资料，不如先迁移高频、在用、责任人明确的内容。
- 试点的首要目标不是搬运文件数量，而是建立唯一批准版本与责任链。

## 范围

- 纳入：最近 90 天更新、每周被使用、存在明确责任人的文档。
- 暂缓：历史归档、无人负责、合规状态未知的文档。
- 一个合理但尚未确认的假设是：试点可由现有项目管理员兼任内容负责人。

## 路径

1. 盘点并冻结试点清单。
2. 清理重复版本并标记唯一批准版本。
3. 迁移内容、权限与责任人。
4. 以查找任务和回滚演练验收。

## 里程碑

- 第 1–2 天：冻结范围。
- 第 3–5 天：清理与标记。
- 第 6–9 天：迁移与抽检。
- 第 10 天：验收与复盘。

## 决策

- 今天确认试点负责人、文档范围、权限原则和第 10 天验收会。
